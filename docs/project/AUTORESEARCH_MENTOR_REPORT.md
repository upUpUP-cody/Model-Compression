# 关于 Autoresearch 仓库对本项目适用性的说明


## 1. Autoresearch 是什么

Autoresearch 是一套**无人值守的短周期实验协议**，不是「大模型预训练框架」。典型用法是：

1. 智能体修改**一个**可编辑脚本；
2. 在**固定墙钟预算**内跑完一次实验；
3. 用**单一指标**判断是否变好；
4. 变好则保留（git keep），否则回退（discard），整夜重复。

原版任务是单卡、约 5 分钟训练一个**小规模**语言模型，优化验证 `val_bpb`。价值在于**高通量方法试错**，不在于训出 frontier 大模型。

---

## 2. 对本项目（E0–E14）能做什么

若把「训练小 GPT」换成「固定稀疏度下的剪枝（及可选短恢复）+ 快速评测」，该协议可以服务本项目的**方法搜索**，例如：

| 可自动化探索的内容 | 与项目的对应关系 |
|---|---|
| Wanda 等剪枝变体、校准与层间稀疏分配 | 服务 E1 类 oneshot 方法改进 |
| 迭代剪枝日程 | 关联 E2，并为后续 E4 等做候选 |
| 短 LoRA / LM recovery 的超参与数据配方 | 服务 E8 / E9 恢复实验准备 |
| 更后阶段的自适应搜索 / 控制器策略 | 仅在 Gate 与 PDF 顺序允许后，对应 E4–E7 / E12–E14 |

**预期产出：** 一夜多轮可比较的候选方法 + 可审计的 keep/discard 记录；有希望的改动再**人工移植**到正式实验 runner，用完整 E 协议复验后，才进入正式报告与 E 地图。

**明确边界：**

- 不替代正式六维评测，不自动判定 Gate A/B 等；
- 一夜循环宜用导师已采用的**快速代理尺子**（如 SST-2 分类准确率），代理分不得直接写回正式 E1/E2 向量；
- 在 Gate A 未通过的前提下，该循环定位为**方法 R&D**，不宣称 Stage D「自主 Agent」已成立。

---

## 3. 为什么不能（也不应）用它训练我们的大模型

这里的「大模型」指本项目使用的 **Qwen2.5-3B 级预训练 / 全量再训练**。

| 原因 | 说明 |
|---|---|
| **目标不一致** | 本项目科学问题是：给定已有 Qwen，压缩前沿、缺口与恢复是否成立；不是再预训练一个新的 3B。 |
| **时间预算不匹配** | Autoresearch 依赖短周期、高重复；3B 预训练单次墙钟极长，一夜只能极少次，失去该框架的核心优势。 |
| **资源不匹配** | 当前基线为单卡；全量持续预训练 3B 不现实，也与 PDF 第一批「1×4090 做压缩评测」的设定不符。 |
| **评测协议冲突** | 正式结论依赖冻结的 E0–E14 与六维 scan；把预训练塞进短循环，既无法完成协议，也会污染实验叙事。 |

**可做的「训练」仅限压缩后的短恢复**（如 E8/E9 量级的少量 step / LoRA），属于**修补**，不是预训练。

---

## 4. 建议结论

1. **可以采用** Autoresearch 的三文件协议思想，作为本仓库旁路的**压缩方法自动试错引擎**，加速剪枝/恢复配方的筛选。
2. **不应期望**用该仓库完成本项目大模型的预训练或替代 E0–E14 正式实验与 Gate。
3. **推荐工作流：** 自动循环出候选 → 人工审阅 → 写入正式 Stage runner → 完整协议复验 → 更新 E 报告。
